### 🧠 What I Learned
*Explain the concepts in your own words.*

A HashMap earns its place whenever I need a single pass through data — it lets me hold onto information as I go instead of scanning back over what I've already seen. What gets stored in the value depends entirely on the problem:
- Character → Frequency
- Number → Count
- Value → Boolean (Seen Before)

The skill isn't memorizing syntax — it's identifying **what piece of information the problem needs me to carry forward** as I move through the input.

---

### 💡 The "Aha!" Moment
*What finally clicked today?*

HashMaps aren't just a duplicate-finding trick.

The real question is:
> **"What do I need to remember so I never have to look backwards?"**

Answer that, and the HashMap practically builds itself.

### 🎤 Interview Notes
*How would I explain this to another engineer or in an interview?*

A HashMap trades memory for speed. Rather than re-scanning an array or string every time I need an answer, I record information as I go so future lookups drop to **O(1)**. The real decision is what to store — here, it's each character's running frequency. The moment a character's count hits two, I can return immediately without touching the rest of the string.
